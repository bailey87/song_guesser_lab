# 干擾版闖關入口與播放權限修正

日期：2026-10-23（台北）。分支：`fix/interference-stage-entry`。

## 問題與修正範圍

使用者回報 Brave 在 `index.html?interference=1` 按闖關後停在首頁。在乾淨 Chromium 中可進入闖關；進一步用新版 HTML 搭配上一版 `b751d27` 的 `interference-options.js`，成功重現首頁不變與未處理錯誤：`Cannot read properties of undefined (reading '歌曲ID')`。

原因是上一版模組讀取 `namedDecoys`，新版 HTML 改傳 `themeOptions`；兩者混用時建立題目便失敗，且原本要建立成功後才切換載入畫面。這能解釋使用者的現象，但無法直接讀取使用者瀏覽器快取，尚不能確認正式網址當時究竟混用了哪些檔案。
程式確實存在播放權限的恢復缺陷：Web Audio「試聽」成功不代表 HTML 音訊播放器已獲得自動播放權限。原曲或延後加入的干擾曲若拋出 `NotAllowedError`，舊程式只顯示一般失敗訊息；重試又清除並重新載入兩首音訊，可能使播放發生在使用者點擊授權時效之外，再次被瀏覽器拒絕。

本次修正：

- 所有七個外部遊戲腳本統一加上版本查詢參數 `v=20261023-stage-fix`，避開舊版無版本網址的快取。
- 先進入載入畫面再建立題目；建立題目失敗時顯示錯誤與「重新產生題目」，避免靜默停在首頁。

- 區分播放權限拒絕與下載失敗，顯示 Brave 網站自動播放設定提示。
- 權限拒絕後保留已就緒的播放器；點「允許播放並重試」時直接啟動同一題，不重新下載。
- 雙播放器已就緒時，在點擊事件中直接呼叫原曲 `play()`，避免先等待不必要的準備步驟。
- 失敗時兩首一起停止、鎖住答題並停止計時；成功恢復後重新給予完整答題時間，不提前記分。
- 畫面殘留的「兩秒」說明修正為 2.5 秒。

網站不能自行變更 Brave 的權限。如果使用者設定持續禁止自動播放，仍須在 Brave 中允許這個網站；本次不要求停用 Shields 或 TLS 驗證。

## 驗證

- `node --test tests/*.test.js`：18/18 通過，新增就緒音訊同步啟播及權限錯誤傳遞測試。
- 新舊檔案混用重現：修正前停在首頁並拋出例外；加入版本參數後，同樣的舊版無版本腳本攔截不再命中，能進入載入畫面且無未處理例外。
- `python tests/stage-entry-smoke.py`：通過。
  - 模擬舊版無版本模組仍在快取中，驗證新版不再使用它。
  - 注入題目建立失敗，驗證錯誤畫面及重新產生題目的恢復流程。
  - 全語系干擾、久石讓干擾、一般模式各完成六關，每關十題，共 180 題，驗證入口、九個選項、過關、紀錄及返回首頁。
  - 兩種干擾模式注入 `NotAllowedError`，確認鎖題、顯示重試、點擊後重用原播放器並恢復。
  - 使用真實 HTML 音訊播放器播放本地生成測試音，確認 2.5 秒加入及 50% 音量。
  - 模擬干擾曲權限錯誤，確認兩曲停止且可重試。
  - 無未處理的 JavaScript 錯誤。

以上是 Chromium 與本地測試音的流程回歸測試，不是 Brave 實機測試，也不是 Apple 歌曲音源的真實播放驗收。先前環境憑證限制仍存在，本次未修改瀏覽器信任庫。

## Brave 試玩檢查

部署本分支後重新整理 `demo.html`，選任一專場、輸入暱稱並試聽，再選闖關。若顯示「允許播放並重試」，點擊一次；若仍被拒絕，從網址列的網站設定尋找自動播放權限並允許本站，再重試。

若仍停在首頁或「正在準備第一首」，需要記錄實際網址、畫面訊息及 Brave 主控台錯誤，分辨部署快取、音源封鎖或其他程式錯誤。推送修正分支不代表正式 Pages 已部署。
