| 真實瀏覽器音訊測試 | 未完成 | Chromium 連線 Apple 預覽發生 `net::ERR_CERT_AUTHORITY_INVALID`；久石讓 smoke test 等待音訊逾時 |

音訊時序與音量測試使用可控制的媒體物件，不能取代真實瀏覽器雙曲播放與人工試聽。55 個 HTTPS 請求使用 Python 的既有系統信任設定，沒有停用憑證驗證。

自動審核拒絕將環境代理 CA 加入 Chromium NSS 信任庫，理由是會持續擴大瀏覽器憑證信任範圍。本次未重試該動作，也未停用 TLS 驗證。須在正常信任 Apple 憑證的瀏覽器繼續執行 `tests/interference-smoke.py`、`tests/hisaishi-smoke.py` 並人工試玩，尤其是 Safari／iPhone 的雙音訊播放。

## 試玩

以靜態 HTTP 伺服器提供本分支，開啟 `demo.html`：

1. 久石讓專場：檢查常用曲名、兩首是否可辨識、其他七個名稱是否合理。
2. 全語系：確認新動漫與歌手題目可抽中。
3. 原曲播放約 2.5 秒後應加入較小聲的干擾曲；選干擾曲仍判錯，答題後兩首應停止。

歷史十輪抽題報告屬於較早題庫，不是這版的十輪測試結果。功能分支推送不等於 GitHub Pages 已部署。
