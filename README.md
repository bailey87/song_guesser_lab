# Song Guesser Lab · 金曲猜歌王

純前端單人猜歌遊戲：聽音樂、從九個歌名選出正解。使用靜態 HTTP 主機即可執行，不需要帳號、後端、資料庫或 npm 依賴。改作自 NTUPM 18th，原始程式授權與著作權聲明保留於 LICENSE。

## 雙曲干擾 Demo

開啟 `demo.html` 可選擇「久石讓專場」或「全部語系」，再輸入暱稱、試聽並選競速／闖關。Demo 入口使用 `index.html?interference=1`，久石讓專場再加 `&pool=hisaishi`；一般 index.html 不開啟雙曲干擾。

- 原曲開始實際播放後才計時；播放進度滿 2 秒，另一首選項歌曲以「目前設定音量 × 70%」加入。原曲維持原音量，設定 80% 時干擾曲為 56%。這是音量係數，不是感知響度或錄音音量正規化。
- 兩首都先準備音源，干擾曲從自己的預覽起點開始；答案永遠是最先播放的原曲。作答、12 秒逾時、重試時兩個播放器一起停止。
- 久石讓題目為 **1 個原曲正解＋1 個真實干擾曲名＋7 個近似名稱**；近似名稱隨機分配為原曲 3／干擾曲 4，或原曲 4／干擾曲 3，兩個真實曲名均在九宮格中。
- 其他歌曲至少保留一個有音源的真實錯誤選項，優先選同分類作干擾，其他七格維持真實歌名。
- 兩首音訊準備或播放失敗時會鎖住題目並提供「重試音訊」，不會用合成音冒充干擾曲。重試同一題不增加分數或換答案。
- Demo 的個人成績／通關紀錄與一般模式分開，跨場歌曲輪替仍共用。此版本未修改一般模式的規則與計分。

瀏覽器的媒體排程與網路緩衝可能造成小幅加入延遲；以原曲播放進度判斷兩秒，不是等待下載兩秒。Chrome 自動測試可驗證雙播放器，iPhone／Safari 的延後播放限制與實際混音聽感仍需實機試玩。

新增 `interference-options.js` 管理選項結構、`dual-audio.js` 管理雙曲時序與停止；音訊準備現在共用進行中的 Promise，避免預載覆蓋正在使用的播放器。

驗證方式：`node --test tests/*.test.js`；有 Playwright 與 Chromium 的環境另可執行 `python tests/interference-smoke.py`，驗證真實雙曲播放、兩秒門檻、70% 音量、選干擾曲判錯、提早作答、逾時停止、錯誤重試及一般模式隔離。

## 這一版的玩法

- **競速**：每場十題，每題 12 秒，答對獲得 300 分加最多 700 分速度獎勵，理論滿分 10,000。
- **闖關**：六關各十題、每題 12 秒；門檻依序為 4,000、5,000、6,000、7,000、8,000、9,000 分。每關重新計分，失敗從第一關重來。
- **一開始全開放**：兩種模式、所有關卡都使用完整 710 首。每回合至少各一首現代華語、華語經典、台語、西洋、韓文、日文，剩餘四題從全曲庫補足。
- **跨場輪替**：同一回合不重複，跨回合優先出未玩過的歌；某類型可用歌曲耗盡後才優先回收最久未玩的歌曲。兩種模式共用紀錄，重新整理後保留。
- **沒有歷史排名**：已移除原社團幹部榜、玩家分布／百分比、Supabase 歷史管理頁與 SQL。只保留這支裝置的個人成績及最高通關紀錄。

輪替只在題目實際進場時記錄，不會把預載、尚未玩的題目算成已玩過。紀錄使用 localStorage；清除網站資料、換瀏覽器／裝置或網站 origin 都會重設。儲存不可用時，當前頁面仍能輪替，重開後無法保留。類型最低出題數會影響各歌曲機率，並非全曲庫每首機率完全相同。

新版個人成績採獨立儲存 key，避免與舊版較窄曲庫的關卡紀錄混算；不會刪除原本瀏覽器中的舊資料。

## 題庫與選曲

六類各新增 50 首後，再於日語區追加 20 首久石讓作品，合計 710 首。久石讓作品不受近五年 J-pop 選曲日期限制。

| 分類 | 原有 | 新增 | 現有 |
| --- | ---: | ---: | ---: |
| 現代華語 mando | 200 | 50 | 250 |
| 華語經典 classic | 60 | 50 | 110 |
| 台語 tw | 30 | 50 | 80 |
| 韓文 kpop | 42 | 50 | 92 |
| 西洋 west | 40 | 50 | 90 |
| 日文 jp | 18 | 70 | 88 |
| 合計 | 390 | 320 | 710 |

新增日韓以 2021-10-22 至 2026-10-22 的熱門／廣為人知作品為主；新增現代華語限近二十年，經典挑長期傳唱作品。這是人工選曲清單，不是即時排行榜排名，也不回溯移除原有較早的日韓歌曲。歌曲年代依 Apple 商店的 releaseDate 檢查，可能與作品最初發行日期不同。

[data/library-expansion-2026-10.json](data/library-expansion-2026-10.json) 保存本次 300 首的分類、Apple track ID、商店曲名、歌手、發行日期與作品連結，可供逐首審閱。日文顯示名部分由 Apple 英文／羅馬字對應回原文。300 個新增預覽均經 HTTP Range 可讀性檢查，但此檢查不等於逐首人工抽聽；有翻唱、音源版本或起點疑慮時，仍需使用 `check.html` 試聽。

## 久石讓主題題目與近似名稱

新增 Summer、那個夏天、人生的旋轉木馬、風之通道、隔壁的龍貓、伴隨著你、魔法公主、阿席達卡與小桑、阿席達卡傳奇、崖上的波妞、娜烏西卡安魂曲、第六號車站、白龍少年、能看見海的街道、旅路・夢中飛行、送行者・記憶、Oriental Wind、花火、媽媽的掃帚、The Rain。

正解採實際曲名或常用中文譯名，來源商店資訊仍保留於 previews.js 與 [data/hisaishi-20.json](data/hisaishi-20.json)。久石讓的每題另有八個人工改寫的近似名稱，例如「人生的旋轉木馬」搭配「人生的旋轉舞台／時鐘／列車」；這些是遊戲干擾標籤，不是聲稱存在的真實作品，也不會被當成題目播放。

近似名稱保存在 named-decoys.js，僅套用於這 20 首，其餘歌曲仍用原本真實歌名選項。所有選項照常洗牌，正解位置仍不連續相同；個別歌手最多兩格的限制只適用於一般真實選項，這些不顯示歌手的虛構標籤不受此限制。答錯後會顯示真正的正解曲名。

## 執行

在專案根目錄：

```sh
python -m http.server 8000
```

瀏覽器連至本機 8000 埠，輸入暱稱並點「試聽」，再選模式。數字鍵 1–9 可作答。部署可使用 GitHub Pages；是否發佈、從哪個分支發佈由 repository 的 Pages 設定決定，推送功能分支不代表已更新正式網站。

## 音訊與網路

`previews.js` 保存 Apple 官方預覽網址，播放時瀏覽器直接串流，不把錄音打包到 repository。玩家端需要 `audio-ssl.itunes.apple.com`；字型需要 `fonts.googleapis.com` 與 `fonts.gstatic.com`。開發者搜尋工具使用 `itunes.apple.com/search`。

首題找不到音源會留在載入頁提供重試；後續缺音源仍可能播放合成示範音。示範音不是原曲，也不能算已修好音源。`audio/` 可放具備使用權的自有片段；不要把第三方試聽下載後重新散布。本地探測第一次失敗後會跳過後續本地探測，混合音源曲庫需留意這個既有行為。

## 主要檔案

| 檔案 | 用途 |
| --- | --- |
| index.html | 畫面、規則、音訊、計分、分享與個人紀錄 |
| named-decoys.js | 久石讓每首八個近似曲名干擾標籤 |
| song-rotation.js | 可測試的跨場輪替與 localStorage 保存 |
| songs.js | 正解題庫 |
| decoys.js | 額外干擾歌名；本次已移除新轉為正解的重複項目 |
| previews.js | 歌曲 ID 對音源與商店資訊 |
| check.html | 人工抽聽與本機標記；預設篩選本次新增歌曲 |
| data/library-expansion-2026-10.json | 本次選曲來源與日期稽核資料 |
| tools/ | 預覽搜尋、干擾題產生、自有錄音剪輯工具 |
| tests/ | 輪替、資料與瀏覽器流程驗證 |
| docs/architecture/ | 原始版本的架構分析，已標示版本邊界 |

調整規則請看 index.html 的 CONFIG／STAGES。維護歌曲以唯一 ID 連結 songs.js 與 previews.js；`node tools/fetch-previews.js` 預設只補缺少音源的 ID，`--only id1,id2` 可重抓指定歌曲。`node tools/build-decoys.js` 會重新建立整份 decoys.js，手動修正不保證保留，執行後務必審閱差異。`tools/clips.csv` 是舊剪輯工作表，不隨題庫自動同步。

## 驗證

不需安裝 npm 套件：

```sh
node --test tests/*.test.js
```

如環境有 Python Playwright 與 Chromium，可執行：

```sh
python tests/browser-smoke.py
python tests/hisaishi-smoke.py
```

瀏覽器測試啟動自己的臨時靜態主機，涵蓋真實音源載入、完成一場競速、跨模式與重新整理避重，以及六關的通過／失敗與首頁返回。測試瀏覽器使用獨立 Storage，不會更動玩家資料。久石讓專項測試以受控的單題曲庫逐首驗證 20 首真實播放、八個近似標籤、九宮格去重與正解判斷，另外檢查普通歌曲未套用虛構選項。

## 十輪自動試玩與抽題紀錄

目前保存的十輪報告來自加久石讓之前的 690 首版本，100 題無重複；這份歷史報告不包含本次新增的 20 首。

在已備妥 Playwright、Chromium 與正確 HTTPS 信任設定的環境執行：

```sh
python tools/autoplay-report.py
```

測試以全新瀏覽器進行十場競速，逐題等待真實音訊開始播放，再自動選正解；若剩三秒仍無進度，會另外記錄為未確認播放後作答；第五場後重新整理以檢查持久化避重。僅縮短答案揭曉停頓，不修改抽題規則。結果寫入 `docs/playtests/autoplay-10-rounds.md` 與 JSON，包含每題歌曲、歌手、分類及跨場重複統計。

預設測試目前 checkout 的本機版本，不能用來判定 Pages 部署是否完成。若要驗證已發佈版本，可加 `--url` 指定 Settings → Pages 顯示的網址；使用 `--output` 可另存報告，避免覆寫既有紀錄。
